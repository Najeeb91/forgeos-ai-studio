# ForgeOS Consolidation Manifest

ForgeOS is the canonical product. AppDeploy, Hatchable, Lovable, Railway, Vercel and GitHub are adapters or reference implementations, never parallel ForgeOS products.

Merged capability sources:
- AppDeploy: authenticated durable runs, explicit AI generation/repair adapters, real build gate, release credential gate, mobile QA contract.
- Hatchable: explicit execution steps, risk/action taxonomy, source snapshots, audit events, deployment observations, brain persistence and controlled migration pattern.
- Lovable: builder-oriented project shell, responsive product information architecture and provider-neutral studio UX patterns.
- Execution Core: state-machine lifecycle, bounded actions, approval gates, cancellation/timeout contracts.
- GitHub: canonical source/CI and portable worker build path.

Non-negotiable:
- No simulated result may be represented as real.
- No deterministic generation fallback is presented as AI.
- Provider failure changes routing, not product architecture.
- High-risk/destructive actions require durable approval.
- Source snapshots are immutable evidence; patches should create a child snapshot.
- Project Memory is the durable context layer; Project Brain is a versioned projection.
- Deployment intent and deployment observation are separate records.
